# UI Style Guide

## Global Background

- 前台允许使用动态背景、渐变光、樱花、萤火、弹幕等氛围组件，但内容可读性优先。
- 后台使用更克制的背景，避免装饰遮挡表格、编辑器和表单。
- 全局背景不得造成滚动卡顿；移动端应减少动画密度。

## GlassCard

- `GlassCard` 用于承载独立信息块、工具面板和重复卡片。
- 不要把卡片嵌套在卡片里。
- 前台卡片可以更有层次，后台卡片应保持信息密度。

## Navigation

- 前台导航保持轻量、清晰、可折叠。
- 后台导航应固定主功能入口：仪表盘、文章、动态、杂谈、草稿、媒体、设置。
- 当前路由必须有明确 active 状态。

## Page Width

- 前台页面内容最大宽度建议控制在 `1180px-1280px`。
- 文章详情正文应窄于首页聚合区域，保证阅读舒适。
- 后台工作区应优先利用宽屏，编辑器和预览可左右分栏。

## Radius And Shadow

- 常规卡片圆角建议 `24px-30px`，工具按钮圆角建议 `12px-16px`。
- 高密度后台区域减少大圆角和重阴影。
- 阴影用于层级，不用于制造大面积发光噪声。

## Hover And Motion

- hover 只做轻微位移、边框、背景或阴影变化。
- 前台可以有卡片动效，后台按钮和表单动效必须快速、稳定。
- 不允许 hover 改变布局尺寸。

## Mobile

- 移动端导航必须可达，按钮文字不得溢出。
- 文章、动态、照片墙、音乐播放器必须在窄屏下保持可读和可操作。
- 装饰特效在移动端降低密度或关闭。

## Empty States

- 每个列表页面都要有空状态。
- 空状态应说明当前没有内容，并提供合理入口，例如去后台创建内容。
- 空状态不得只显示空白卡片。

## Loading States

- API 加载中的列表和详情页需要显示加载状态或骨架。
- 加载失败要显示可读错误，不只在控制台报错。
- 后台保存、上传、AI 请求必须有 pending 状态。

## Admin Layout

- 后台不做营销式大 Hero。
- 仪表盘、编辑器、设置页优先服务重复操作：入口清晰、按钮靠近上下文、反馈明确。
- 表单化设置优先于直接编辑 JSON；JSON 编辑可作为高级兜底。
