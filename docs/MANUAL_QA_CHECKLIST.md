# Manual QA Checklist

本清单用于浏览器人工回归。除非全部相关项通过，否则不要把 `docs/XINGHUI_PARITY_MATRIX.md` 中对应模块标记为 `已完成`。

## 前台文章详情

- [ ] `/posts/srblogs-p0-20260502130609` 可打开。
- [ ] `/posts/vue-fastapi-blog` 可打开。
- [ ] 标题、日期、标签、摘要正确。
- [ ] Markdown 正文正常。
- [ ] 代码块高亮正常。
- [ ] TOC 显示并可点击滚动。
- [ ] 图片加载失败有兜底。
- [ ] 分享按钮点击不报错。
- [ ] 不存在 slug 显示 404/错误状态，不白屏。
- [ ] 390px 移动端可读。

## 前台首页响应式

- [ ] 1440px：首页 Hero 和 ProfileCard 正常并排，右侧不裁切，无横向滚动条。
- [ ] 1280px：ProfileCard 不被裁切，SiteDashboard 统计卡片不溢出，顶部导航不溢出。
- [ ] 1024px：首页 Hero 和 ProfileCard 自动变为单列或合理压缩，fixed 控件不遮挡内容，无横向滚动条。
- [ ] 390px：首页可读可操作，导航可操作，统计卡片换行，右侧/底部浮动控件不挡正文和按钮。
- [ ] 1440px、1280px、1024px、390px 下主内容左右边距基本一致，页面不能视觉上向右顶出。
- [ ] 顶部导航、Hero/ProfileCard、SiteDashboard、LatestPosts 使用同一主内容宽度，不出现导航居中但首页右贴边。
- [ ] 右侧主题/背景/弹幕按钮不遮挡 ProfileCard 或主要内容。
- [ ] FloatingPlayer 不遮挡文章内容、评论区和主要按钮。
- [ ] 页面整体无横向滚动条，图片和卡片最大宽度不超过 viewport。
- [ ] 即使没有横向滚动条，也不能出现 ProfileCard、头像、昵称、统计、社交按钮或 SiteDashboard 最右侧卡片被裁切；出现裁切即为不通过。
- [ ] 首页“最新文章”不是横向滚动轨道；4 篇文章在当前主容器宽度下应换到第二行第一列，而不是继续排成第一行第四列。
- [ ] 文章数量从 1、2、3、4、5 变化时，首页主容器宽度和左右边距不跳变。

## 后台 Markdown 编辑器

- [ ] 点击“插入预览测试样例”后，右侧预览是真实 Markdown 渲染，不是纯文本。
- [ ] 一级标题明显大于二级标题，二级标题明显大于三级标题。
- [ ] 无序列表显示项目符号。
- [ ] 有序列表显示 1、2、3 编号。
- [ ] blockquote 有引用样式。
- [ ] inline code 有等宽字体和背景。
- [ ] fenced code block 有等宽字体、背景和横向滚动。
- [ ] table 显示为表格，窄屏不横向撑破页面。
- [ ] link 有链接样式。
- [ ] image 最大宽度不超过预览区。
- [ ] 预览仍经过 DOMPurify 清洗。

## 后台评论管理

- [ ] `/admin/comments` 可进入。

- [ ] 登录后直接请求 `GET /api/admin/comments/index` 返回 200，不再是 404。
- [ ] 页面打开后不需要手动输入 slug。
- [ ] 默认显示有评论的内容索引。
- [ ] 索引项显示标题、resource、slug、评论数和最近更新时间。
- [ ] 点击索引项后自动加载对应评论。
- [ ] 当前选中项有 active 状态。
- [ ] 删除评论成功。
- [ ] 删除不存在评论显示错误。
- [ ] 删除后前台评论区同步变化。
- [ ] 删除后评论列表数量减少，索引 count 同步刷新。
- [ ] 删除前 `backend/data/comments/.backups` 生成备份。
- [ ] 手动 resource/slug 加载只在“高级加载”折叠区中出现，不作为主流程。

## 后台写作

- [ ] `/admin/posts` 可进入。
- [ ] 文章列表显示标题、slug、日期、标签、draft 状态。
- [ ] 全部/已发布/草稿筛选正确。
- [ ] 点击“编辑”进入写作页并加载该文章 Markdown 正文和元信息。
- [ ] “前台预览”能打开对应前台详情地址。
- [ ] 后台新建非草稿文章。
- [ ] 文件写入 `backend/data/posts`。
- [ ] 前台文章列表出现。
- [ ] 前台文章详情可打开。
- [ ] 后台新建草稿文章后，`backend/data/posts` 有文件，但前台文章列表不显示。
- [ ] 草稿入口可看到 draft=true 文章。
- [ ] 草稿可继续编辑。
- [ ] 草稿“立即发布”后 draft=false，前台文章列表出现，前台详情可打开。
- [ ] 草稿“发布加入暂存”不会立刻写后端，点击暂存区“应用”后才发布。
- [ ] 编辑已发布文章后，保存成功提示可见，刷新前台详情可看到更新。
- [ ] 删除文章前有确认。
- [ ] 删除文章后 `backend/data/posts/.backups` 生成备份。
- [ ] 删除文章后前台文章列表不再显示该文章。
- [ ] 删除文章后前台详情显示 404/错误状态。
- [ ] 非法 slug 的 UI 错误提示可见。
- [ ] 空 slug 的 UI 错误提示可见。
- [ ] 空标题的 UI 错误提示可见。
- [ ] 重复 slug 的 UI 错误提示可见。
- [ ] 网络错误或保存失败时 UI 显示可读错误，不只在控制台报错。
- [ ] 保存成功时 UI 显示成功提示。
- [ ] 页面明确区分“保存”直接持久化和“加入暂存”本地 pendingOperations。

## 后台暂存队列第一阶段

- [ ] 写作页点击“加入暂存”后不立刻写入后端。
- [ ] 右侧“操作暂存区”显示待执行操作列表。
- [ ] 每条操作显示操作类型、目标标题、slug、状态、创建时间。
- [ ] 队列状态只使用 `editing`、`pending`、`applied`、`failed`。
- [ ] 点击“应用”后才调用真实后端 API 写入。
- [ ] 应用成功后状态变为 `applied`。
- [ ] 应用失败后状态变为 `failed`，并显示错误信息。
- [ ] failed 操作可以重试或移除。
- [ ] pending 操作可以移除。
- [ ] 页面明确提示第一阶段为前端本地队列，刷新页面会丢失。
- [ ] 文章新建可进入暂存并应用成功。
- [ ] 文章编辑可进入暂存并应用成功。
- [ ] 文章删除可进入暂存并应用成功，删除前有备份。
- [ ] 草稿发布可进入暂存并应用成功。
- [ ] 图片上传、Secret 修改、评论管理不进入本地 pendingOperations。
